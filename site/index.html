Why this exists

AI web-coding nails the first 80%.
The last 20% is a judgement problem.

An AI coding agent can generate a complete, working web page from a prompt — structure, styling, responsive behaviour, all of it. But pages are not finished when they compile. They're finished when someone looks at them and adjusts what doesn't feel right — and that is exactly where the prompt-driven workflow stops working.

01

Design judgement needs a visual loop

Nobody decides between 15px and 16px by reading prose — not even the designer who wrote the spec. The decision is made against direct visual feedback: nudge, look, judge, nudge again. Web-coding agents break that loop — every tweak becomes a prompt, a rebuild, a reload, and a guess at whether the guess landed.

02

Natural language can't carry a nudge

"Move it a bit left" still has to be interpreted — by a model, at token cost, with a render cycle attached, and no guarantee that "a bit" means the same thing twice. A drag says it in one second, exactly. This editor turns a hundred descriptive round-trips into a hundred direct manipulations — then one save.

03

Handoff without translation

The agent builds the page; the designer adjusts it directly on the built page. No annotated screenshots, no "padding-top: 13px not 12px" messages, no developer guessing what the design meant. The correction lands where it will ship — in the CSS, in the units the layout was written in.

01

Point. Grab. Move.

Click selects, double-click drills into nested structures, and dragging moves the element itself — no property panel detour, no pixel arithmetic, no describing the distance in words. Where you drop it is where it goes.

02

Grab any corner. Resize.

Every side and corner of the selection is a handle — drag one and the element follows, with the size badge riding the pointer in real pixels. Underneath, the value is written back in its authored unit — %, cqw, whatever the layout was built in.

03

Words are editable too

Double-click any text and retype it in place — delete letter by letter, type letter by letter, exactly like the tools your hands already know. Enter commits, Esc cancels, and every keystroke is undoable.

04

Type size, in the author's own units

The Typography group edits size, line-height, letter-spacing and colour through structured controls — and a fluid 5.4 cqw stays cqw after you change it. The responsive system survives the edit, because the unit was never flattened to pixels.

05

One of seven, or all seven

Seven cards share one selector. Select one and the editor warns you. Hover All 7 and every sibling lights up — the blast radius, visible — and an edit there repaints the whole set. Switch to Only this and the same control touches one card alone. Same gesture, two scopes, and you always see which one you're in.

06

Every parameter, structured

Gradient angle and stops, drop shadows, corner radius, fill, stroke, opacity, spacing — each is a real control with its own editor, not a raw CSS textarea. Groups you haven't touched stay folded behind a +; touch one and it opens with sensible defaults.

07

Swap the artwork, keep the frame

One green button replaces an image — your OS file picker opens, you pick a file, the frame stays exactly where it was. Works for <img> elements and CSS background-image alike, because the intent is the same even when the markup differs.

08

Hide the chrome. Judge the page.

Sometimes you need the tools gone to see the composition whole — the toolbar blocking the corner is enough to throw off a judgement. Click the mark and it collapses into its own logo: red when shut, blue when open. Your selection, the inspector and every edit keep working while it's away; click again and it's back. That's the whole interaction.

09

A full pass, no cuts

Everything above, unedited, on one real product screen: retype the headline, bump its size, recolour the badge, swap a release cover. This is what the last 20% looks like when it takes minutes instead of prompt cycles.

10 — when you're done adjusting

One save,
three shapes.

Edits accumulate as a pending batch — the count rides on the Save button — and you decide what form they leave in:

Save ⌘S

Writes the whole batch into the project's own CSS overrides file, in authored units. The page you were looking at is now simply the page.

Export CSS patch

A .css file of just the changes — with a header telling any agent or developer exactly how to merge it. A designer's adjustments enter the engineering workflow as a readable diff, not a conversation.

Export clean copy

The whole site with the editor stripped out — what you ship when the review is done.

Built under four rules
  1. No AI-flavoured styling. No soft purple gradients, no glass blur. Hairline grid, hard accent colours, square corners, single hard shadows.
  2. Peers stay peers. Sibling controls are equal-width and ever-present; unavailable ones grey out in place instead of vanishing and reflowing the row.
  3. State is visible. Saved vs dirty, open vs shut, hovered vs not — nothing important hides behind a convention you have to know.
  4. The page stays the page. Without ?edit=1, nothing loads. The shipped site is byte-for-byte unaffected.
Install

Two files. One loader.

Hand it to your AI agent — it is distributed as a skill, and the agent wires it into your site for you. Or do it by hand in a minute:

<!-- before </body> — loads only when the URL carries ?edit=1 -->
<script>
  if (location.search.indexOf("edit=1") !== -1) {
    var css = document.createElement("link");
    css.rel = "stylesheet";
    css.href = "tools/visual-editor.css?v=18";
    document.head.appendChild(css);
    var js = document.createElement("script");
    js.src = "tools/visual-editor.js?v=18";
    js.defer = true;
    document.body.appendChild(js);
  }
</script>
